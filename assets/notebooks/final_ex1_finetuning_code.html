This module executes the importation of software libraries and the acquisition of the target dataset, providing the mathematical and structural foundation for the experiment. The pandas library is utilized for data frame management and results exportation, allowing for the handling of heterogeneous data types that standard Python arrays cannot manage. The numpy library is essential for performing numerical operations on matrices, specifically enabling the vectorized calculations required for gradient optimization. For visual analysis, matplotlib.pyplot is included to generate diagnostic charts that translate abstract model weights into interpretable deliverables.

The load_wine dataset consists of chemical analysis results from 178 wine samples grown in the same region in Italy. These samples are categorized into three distinct cultivars, identified as class_0, class_1, and class_2. Each sample includes 13 chemical features which serve as the independent variables for the classification models. These attributes are scientifically significant: - Alcohol, Malic Acid, and Ash: Represent the basic chemical composition and acidity profiles of the grapes. - Alcalinity of Ash and Magnesium: Reflect the mineral content absorbed from the Italian soil. - Total Phenols, Flavanoids, and Nonflavanoid Phenols: Vital antioxidants that define the wine's structure and aging potential. - Proanthocyanins and Color Intensity: Influence the visual and tactile profile of the wine. - Hue and OD280/OD315 of diluted wines: Measures of protein content and color stability. - Proline: An amino acid that varies significantly between different vine cultivars.

In the final steps of this module, chemical measurements are assigned to X, while categories are assigned to y to satisfy the Supervised Learning paradigm. A pandas DataFrame is created to combine these components, followed by the .head() method to perform a mandatory Structural Validation check, ensuring data integrity and alignment before the models are initialized.

2. Data Partitioning and Cross-Validation Setup

[2]:
# Partitioning: 80% Training, 20% Testing
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, random_state=42, stratify=y
)

# Define 10-fold Cross-Validation
cv_fold = KFold(n_splits=10, shuffle=True, random_state=42)

This module handles the critical task of data partitioning and cross-validation configuration to ensure model reliability. The train_test_split function is statistically necessary to create a hold-out set (20%) for estimating the "True Error" of the models on unseen data, preventing the developer from being misled by overfitting. The use of stratify=y is critical because the Wine dataset contains specific class frequencies; stratification ensures that each cultivar is proportionally represented in both the training and testing sets, maintaining the statistical validity of the final evaluation metrics.

The KFold function is implemented to solve the Variance Problem inherent in single data splits. By setting n_splits=10, the training data is rotated through ten iterations, where each fold serves as a validation set. This generates a "Mean CV Accuracy" that is far more representative of general performance. The shuffle=True parameter is mandatory because wine datasets are often sorted by class; without it, a validation fold might accidentally contain only one type of wine, making it impossible for the model to learn a proper decision boundary.

# --- MODEL A: Multinomial Logistic Regression (MLR) ---
pipe_mlr = Pipeline([
    ('scaler', StandardScaler()),
    ('model', LogisticRegression(max_iter=10000))
])

param_grid_mlr = {
    'model__C': [0.01, 0.1, 1, 10, 100],
    'model__solver': ['lbfgs', 'saga'],
    'model__penalty': ['l2']
}

grid_mlr = GridSearchCV(pipe_mlr, param_grid_mlr, cv=10, scoring='accuracy')
grid_mlr.fit(X_train, y_train)
GridSearchCV(cv=10,

                         'model__penalty': ['l2'],
                         'model__solver': ['lbfgs', 'saga']},
             scoring='accuracy')

This module executes the core optimization for the Multinomial Logistic Regression (MLR) model. Note that the multi_class='multinomial' parameter was explicitly removed to resolve the following error: FutureWarning: 'multi_class' was deprecated in version 1.5....

In modern scikit-learn versions, the multi_class parameter is removed because the algorithm is now designed to automatically select the most appropriate strategy (Multinomial vs. One-Vs-Rest) based on the data and solver provided. For a 3-class problem like the Wine dataset, the model defaults to multinomial logic automatically. Leaving this to the default value ensures future compatibility and cleaner code.

The Pipeline ensures that StandardScaler is applied specifically to training folds to prevent data leakage. Scaling is mathematically mandatory because the lbfgs and saga solvers are sensitive to feature magnitudes; normalization ensures faster convergence and prevents features with larger scales (like Proline) from dominating the weight calculations.

4. Implementing the Linear SVM Pipeline

# --- MODEL B: Linear Support Vector Machine (Linear SVM) ---
pipe_svm = Pipeline([
    ('scaler', StandardScaler()),
    ('model', LinearSVC(dual=False, max_iter=10000))
])

param_grid_svm = {
    'model__C': [0.001, 0.01, 0.1, 1, 10, 100]
}

grid_svm = GridSearchCV(pipe_svm, param_grid_svm, cv=10, scoring='accuracy')
grid_svm.fit(X_train, y_train)
GridSearchCV(cv=10,
             estimator=Pipeline(steps=[('scaler', StandardScaler()),
                                       ('model',
                                        LinearSVC(dual=False,
                                                  max_iter=10000))]),
             param_grid={'model__C': [0.001, 0.01, 0.1, 1, 10, 100]},
             scoring='accuracy')

This module implements the geometric classification approach using a Linear Support Vector Machine (LinearSVC). Normalization via StandardScaler is essential because SVMs are distance-based algorithms; unscaled data would distort the calculation of the optimal hyperplane. The dual=False parameter is chosen for computational efficiency, as the number of samples in this experiment is smaller than the number of features. The GridSearchCV tunes the C parameter, which serves as the "penalty" for misclassified points. This allows the experiment to determine if a "Soft Margin" (low C) or a "Hard Margin" (high C) is more effective at generalizing the chemical markers of the wine cultivars.

def process_results(grid, name, X_test, y_test):
    best_idx = grid.best_index_
    mean_acc = grid.cv_results_['mean_test_score'][best_idx]

    print(f"\n{'='*10} {name} {'='*10}")
    print(f"Best Parameters: {grid.best_params_}")
    print(f"Best CV Accuracy: {mean_acc:.4f}")

    # Final Testing Set Evaluation
    y_pred = grid.predict(X_test)
    kappa = cohen_kappa_score(y_test, y_pred)

    print("\nConfusion Matrix:")
    print(confusion_matrix(y_test, y_pred))
    print(f"\nKappa Score: {kappa:.4f}")
    print("\nClassification Report:")
    print(classification_report(y_test, y_pred, target_names=wine.target_names))

    return grid.best_estimator_.named_steps['model'].coef_

This module defines the process_results function to translate optimized models into scientific performance reports, while automating the documentation and visualization of the experimental outcomes. The primary objective is Final Testing Set Evaluation; although the models were tuned using cross-validation on the training set, these final metrics are calculated using the 20% hold-out X_test and y_test to obtain an unbiased estimate of real-world performance. The Cohen’s Kappa Score is implemented because accuracy alone is insufficient for multi-class problems, as it accounts for the probability of random guessing to provide a true measure of classification reliability. To pinpoint specific model weaknesses, a Confusion Matrix and a detailed Classification Report are generated, revealing "confusion pairs" and cultivar-specific precision and recall metrics. Beyond evaluation, the function returns the .coef_ attribute from the pipeline’s best estimator, which is then used to calculate the mean absolute magnitude of numerical weights across all classes. This enables the generation of an excel files, a side-by-side bar chart comparison that visualizes the importance of each chemical marker for both the Multinomial Logistic Regression and Linear SVM models. Finally, the module ensures auditability by exporting the comprehensive cross-validation results for both algorithms into a structured Experiment_Log.xlsx file.

This final module generates the visual deliverables to compare feature importance across the two models. In a multi-class context, coefficients are generated per class; therefore, the code calculates the Mean Absolute Magnitude across the three cultivars to identify features that are globally influential. Sorting the features via np.argsort is a mandatory readability step, allowing the researcher to immediately identify the most and least significant predictors (such as Proline or Alcohol).

The use of a vertical stack (subplots(2, 1)) with horizontal bars (barh) is a structural choice to ensure that the 13 categorical labels remain legible and untruncated. Finally, the plt.savefig function is used to persist the chart as Figure_1_Importance_Comparison.png, providing a permanent analytical record of which chemical markers provide the strongest signal for distinguishing Italian wine cultivars.
